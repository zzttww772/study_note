## 一、向量、嵌入与向量空间

### 1.1 向量、维度、点积

**向量**就是一串有序的数：`[0.6, 0.8]` 是 2 维，`[0.1, −0.3, 2.7, …]` 是 d 维。神经网络内部的一切（图片、文字、中间结果）最终都表示成这种数字串。

**点积（内积）** 是最基本的运算：

```
a · b = a₁b₁ + a₂b₂ + … + a_db_d
```

手算一例：

```
a = [0.6, 0.8]      b = [0.28, 0.96]
a · b = 0.6×0.28 + 0.8×0.96 = 0.168 + 0.768 = 0.936
```

几何上，点积同时受**长度**和**夹角**影响：

```
a · b = ‖a‖ × ‖b‖ × cos θ
```

⚠️ 正因为混进了长度，点积不能直接当作"相似度"。**下一章要做的就是把长度除掉。**

### 1.2 嵌入：把图和文都变成向量

神经网络只认识数字。**嵌入（embedding）就是把一张图、一句话压成一个固定长度的向量**（CLIP 里是 512 维的一串浮点数）。

💡 类比：给每张图、每段文字在同一张地图上打一个坐标点。"猫的照片"和 "a photo of a cat" 应该落在同一个街区，"狗的照片"离它们远一点。

三个容易想错的地方：

1. **维度数 ≠ 概念数**。512 维不是"能装 512 个概念"，概念是若干方向的组合。
2. **空间不是整齐分区的仓库**。概念是连续渐变的，不是一格一格摆好的——正因为连续，才能做图文检索这类操作。
3. **相似度高 ≠ 因果相关**。它只说明在这个训练目标下方向接近。

📌 这些向量不是人手工设计的，而是模型训练出来的（怎么训练见第四章，往哪个空间对齐见第五章）。

### 1.3 词嵌入：文本侧的特例

词嵌入就是"把词变成稠密向量"。

**它解决了 one-hot 的两个毛病**：传统 one-hot 用"词表长度"维的向量，只有自己那一格是 1——维度爆炸，且任意两个词的余弦都是 0，表达不了相似性。稠密词嵌入压到几百维，相近的词方向接近。

**经典性质**：同一方向的偏移带走同一语义。

```
king − man + woman ≈ queen
```

这不是设计出来的，而是训练后自然涌现的结构。

**静态 vs 上下文相关**：

|          | 静态（word2vec / GloVe）                | 上下文相关（ELMo / BERT / GPT） |
| -------- | --------------------------------------- | ------------------------------- |
| 一个词   | **一个固定向量**                  | 不同句子里**向量不同**    |
| 一词多义 | `bank`（银行/河岸）共用一个向量，分不开 | 靠上下文区分                    |
| 输出单位 | 词级                                    | 整句 / 整段                     |

**CLIP 的文本编码器属于右边**：它读完整句话，输出的是**句子级向量**，不是一个词的向量。

文本侧的完整链条（§2.4）：

```
文本 → BPE 分词（词表 49,152）→ 查 token 嵌入表 → 加位置编码
     → 12 层 Transformer → 取 [EOS] 位置 → 句子向量
```

两个细节：

1. **输入单位是 BPE token，不是"词"**。`embedding` 可能被切成 `embed` + `ding`。
2. **词嵌入只是中间产物**，CLIP 从不为"词向量"本身优化，它要的是整句与整图能对上。

📌 这里不展开 Transformer：只需知道它让每个 token 根据上下文更新自己，最后用一个特殊位置 `[EOS]` 的激活代表整句。

## 二、余弦相似度

### 2.1 定义

把点积里的长度除掉，只剩夹角：

```
cos(a, b) = (a · b) / (‖a‖ ‖b‖)        取值范围 [−1, 1]
```

- **1** = 同向，**0** = 正交（无关），**−1** = 反向
- 只看方向，不看长度

### 2.2 手算

```
a = [1, 0]        b = [0.7, 0.7]
a · b = 0.7
‖a‖ = 1,  ‖b‖ = √(0.49+0.49) ≈ 0.99
cos = 0.7 / 0.99 ≈ 0.707        → 夹角约 45°
```

### 2.3 它为什么适合做"相似度"

- **只看方向**：同一段语义无论表达长短，方向应一致
- **有界**：结果永远在 [−1, 1]，便于比较和后续处理
- **可矩阵化**：后面要算 N×N 个两两相似度，用矩阵乘法一次算完（第六章）

⚠️ 余弦只衡量方向，不衡量"含义深浅"。两个无关向量也可能因为训练偏差而接近——这也是 1.2 里"相似 ≠ 因果"的来源。

## 三、归一化

### 3.1 定义

把向量除以它自己的长度（L2 范数）：

```
‖v‖₂ = √(v₁² + v₂² + … + v_d²)      ← 长度
v̂ = v / ‖v‖₂                        ← 归一化后 ‖v̂‖₂ = 1
```

手算：

```
v = [3, 4]        ‖v‖ = 5        v̂ = [0.6, 0.8]
v = [2, −1, 2]    ‖v‖ = 3        v̂ = [0.667, −0.333, 0.667]
```

### 3.2 几何意义

所有向量都被压到**单位球面**上（2 维是圆，3 维是球，512 维是"超球面"）。方向一个都没变，变的只有长度。

于是两个向量之间只剩一个自由度：**夹角**。

📌 归一化之后，余弦就等于点积，除法彻底消失：

```
cos(â, b̂) = â · b̂
```

📌 一个值得记住的数：512 维空间里，随机两个方向几乎必定接近正交（余弦 ≈ 0）。这条直觉在第九章解释"训练开始时为什么分数全是 0"时会用到。

### 3.3 CLIP 为什么必须归一化

1. **省计算**。两两相似度矩阵有 N² 个元素（N = 32,768 时约 10.7 亿），归一化后相似度退化成纯矩阵乘法，一次算完。
2. **尺度一致**。不归一化的话，长度大的向量在点积里天然占优，相似度会被"模长"污染，而不是纯语义。
3. **数值可控**。分数被限制在 [−1, 1]，后面乘温度放大时量级可预测（第八章）。

### 3.4 数学性质

| 性质           | 说明                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| 保方向         | 除以正的标量，方向不变                                                        |
| 尺度不变       | `normalize(c·v) = normalize(v)`（c > 0），图像整体变亮、文本变长，结果一致 |
| 非线性         | `normalize(a+b) ≠ normalize(a) + normalize(b)`，不能拆开                   |
| 与欧氏距离等价 | `‖â − b̂‖² = 2 − 2cos`，"余弦最近"与"欧氏最近"在球面上是同一件事     |
| 梯度是投影     | 反向传播时梯度自动去掉"沿向量自身"的分量，只在切空间更新                      |

### 3.5 实现细节

```python
def l2_normalize(x, eps=1e-12):
    return x / np.maximum(np.linalg.norm(x, axis=-1, keepdims=True), eps)
```

- 必须防零向量除零；用 `np.maximum`（而非 `norm + eps`）更稳：既防 0，又不改变正常值的量级。
- 为什么用 L2 而不是 L1：L1 归一化产生稀疏、棱角分明的结果，且不可导点多、梯度不稳；L2 处处可导、各向同性。

### 3.6 它会丢掉什么

模长信息。若模长本身有含义（某些模型里模长编码置信度或词频），归一化就等于扔掉了该信号。CLIP 的判断是：**语义主要在方向上，模长是干扰**。

### 3.7 三个近邻概念，别混

| 名词 | 是什么 | 和 L2 归一化的关系 |
|---|---|---|
| **L2 归一化** | 除以 L2 范数，长度 → 1 | 本体，作用在向量上，前向 |
| **标准化（z-score）** | 减均值、除以标准差 | 也是归一化，但改变分布位置，不是投影到球面 |
| **L2 正则化 / 权重衰减** | 惩罚权重的 L2 范数 | 名字同源，用途无关；作用在**训练**上（见 4.5） |
| **LayerNorm** | 对每层激活做 z-score，含可学习参数 | 也是前向，但对象是中间激活（见 4.5） |

**一句话记：归一化改数据（前向），正则化改学习（训练）。**

## 四、神经网络怎么学

前面所有"投影矩阵""嵌入空间"都是**学出来的**。这一章补上"学"这件事的最小机制。

### 4.1 参数与前向传播

**参数（权重）**就是模型里那些数字，形状是矩阵，一开始随机。**前向传播**就是"输入 × 参数 → 输出"：

```
输出 = 输入 @ W
```

📌 形状规则：`[n, d] @ [d, k] → [n, k]`。中间维度 `d` 必须对上，输出维度由 `k` 决定。

### 4.2 损失函数

**损失（loss）是一个数**，衡量"当前输出离正确答案有多远"。训练的目标就是把它压小。

不同任务用不同损失；本书后面会遇到的是**交叉熵**（第十章）。

### 4.3 梯度与反向传播

**梯度**是损失对某个参数的偏导，告诉你"这个参数往哪个方向调、调多少，损失下降最快"。

对 `输出 = 输入 @ W` 这种结构，链式法则给出：

```
∂loss/∂W = 输入ᵀ · ∂loss/∂输出
             ↑         ↑
         这一层的输入   从后面传回来的"误差信号"
```

💡 直观理解：误差信号说明"输出该往哪挪"，输入则决定"哪条通路该负责这个改动"，两者相乘就是该通路要改的量。

**反向传播**就是把误差信号从损失开始，逐层往回算的过程。

### 4.4 优化器与常用超参

| 名词 | 含义 |
|---|---|
| **学习率** | 每次更新走多大一步 |
| **Adam** | 一种自适应优化器，按梯度的一阶/二阶统计调整步长 |
| **batch** | 一次前向+反向用多少个样本 |
| **epoch** | 把整个数据集过一遍 |
| **学习率衰减** | 训练后期把步长调小，帮助收敛（CLIP 用余弦调度） |

### 4.5 权重衰减与 LayerNorm

训练时还有两个常见组件，正好把 3.7 里的疑点补完：

**权重衰减（weight decay / L2 正则化）**：在更新时让权重按比例缩小一点，防止过拟合、限制权重大小。

```
普通更新：  w ← w − η·∂loss/∂w
带衰减：    w ← w − η·(∂loss/∂w + λw)
```

**LayerNorm**：对一层的激活做 z-score，再乘可学习缩放（gain）、加偏置（bias）。它让每层数值稳定，本身不是正则化。

📌 论文 §2.5 说"对所有**非增益/偏置**的权重施加解耦权重衰减"——因为 LayerNorm 的 gain/bias 本来就该自由，惩罚它们反而有害。

⚠️ `weight decay` 与"L2 正则化"严格说只在 SGD 下等价；Adam 里必须用解耦版本（AdamW）才等价，论文用的正是解耦版本。

### 4.6 小结

```
参数随机 → 前向算输出 → 算损失 → 反向算梯度 → 优化器更新参数 → 重复
```

后面看到的每一个矩阵（包括第五、九章的 `W_i`、`W_t`）都遵循这个循环。

## 五、投影层与共享空间

### 5.1 问题：两个编码器的输出对不上

CLIP 有图像编码器和文本编码器，它们分别输出 `d_i` 维和 `d_t` 维的向量（比如 2048 和 512）。这两个向量**不能直接比较**：

1. **维度不同**：`[n, 2048] @ [n, 512]ᵀ` 数学上不成立。
2. **语义轴不同**：就算硬凑成同维度，图像的"第 7 维"和文本的"第 7 维"也毫无关系。

### 5.2 它是什么

**投影就是一个线性层（矩阵乘法），把编码器输出的 `d_i` 维特征映射到共享空间的 `d_e` 维。**

```
I_f  : [n, d_i]      图像编码器输出
W_i  : [d_i, d_e]    可学习的投影矩阵
I_e  : [n, d_e]      I_f @ W_i，进入共享空间
```

**没有偏置项，也没有激活函数**，就是纯粹的 `X @ W`。论文图 3 的注释写得很直白：`W_i[d_i, d_e] - 图像到嵌入的学习投影`。

文本侧同理：`T_f [n, d_t] @ W_t [d_t, d_e] → T_e [n, d_e]`。

### 5.3 什么是"共享空间"

两个模态各用自己的投影，压到**同一个** `d_e` 维空间：

```python
I_e = l2_normalize(I_f @ W_i)   # 图像 → 共享空间
T_e = l2_normalize(T_f @ W_t)   # 文本 → 共享空间
```

**这才是"多模态嵌入空间"里"多模态"的实际含义**：不是把图片和文字拼在一起，而是让它们在同一个坐标系里可比。

⚠️ **论文之外的延伸**：Liang et al. (2022) "Mind the Gap" 发现 CLIP 的图与文实际聚成两个略微分离的"锥形区域"，并非完全混在一起。这是后续研究的发现，论文的假设是两者共享同一空间。

### 5.4 它怎么学出来

`W_i` / `W_t` 不是算出来的，是**随机初始化 + 反向传播训练出来的**，和别的权重一样是普通参数。

**① 初始化**：随机数（通常按 Xavier / Kaiming 之类方案采样）。📌 论文 §2.4 只提到 ViT 用了"稍有不同的初始化方案"，没有公开投影矩阵的具体分布。

此时随机矩阵把图文乱混，两两相似度接近 0（见 3.2 的"512 维随机近正交"），模型等于在瞎猜。

**② 反向传播**（机制见 4.3）：

```
∂loss/∂W_i = I_fᵀ · ∂loss/∂(I_f @ W_i)
```

哪类图像总被错配到哪类文本，`W_i` 就往那些方向调整。

**③ 训练完是什么**：一组固定浮点数，存在 checkpoint（`.pt`）里，推理时直接加载。代码里通常挂在 `model.visual.proj`（`W_i`）和 `model.text_projection`（`W_t`），不同实现命名略有差异。

📌 **`W_i` 与 `W_t` 没有被单独训练**：它们和两个编码器共用同一个损失、同一次更新（整体流程见 9.4）。

### 5.5 几何理解：只有"旋转"部分有意义

任何矩阵乘法都可以分解成"旋转 → 缩放 → 旋转"（SVD）。`W_i` 干的事就是：把 `d_i` 维线性地映射到 `d_e` 维，顺带旋转，让语义方向对齐。

📌 因为**投影后面紧跟 L2 归一化**，`W` 的整体缩放会被直接抹掉：乘 2 还是乘 100，归一化后完全一样。**真正起作用的只有它的"旋转"部分。**

⚠️ 这里的"投影"是**线性投影层**的工程叫法，**不是**几何意义上的正交投影。

### 5.6 为什么偏偏是线性的

📌 论文 §2.3 交代过：

- 早年 SimCLR 那套做法会在嵌入前加一个**非线性投影头**（两层 MLP）
- CLIP 把它**去掉了**，只保留线性投影
- 作者说没观察到训练效率的差异，推测非线性投影可能只跟纯图像自监督方法的细节共同适应

含义：**语义对齐主要靠编码器和对比损失完成，投影层只做线性重排**，简单就够了。

### 5.7 三个"投影"别搞混

| 名称              | 在哪                   | 干什么                                |
| ----------------- | ---------------------- | ------------------------------------- |
| `W_i` / `W_t` | 编码器之后、归一化之前 | 把两个模态对齐到共享空间              |
| Q/K/V 投影        | Transformer 每一层内部 | 生成注意力用的查询/键/值              |
| 正交投影          | 线性代数概念           | 把向量投到子空间上，CLIP 里没有这东西 |

### 5.8 四个常见问题

**Q：能不能用数学直接解出来？**
不能。最优值取决于 4 亿对数据的具体分布，没有闭式解，只能迭代优化。

**Q：能不能直接拿别人的 `W_i` 用？**
不能。它和**特定编码器**共同适应；换个图像编码器，"方向含义"就全对不上。

**Q：为什么训练开始时分数接近 0？**
随机投影 + 随机编码器 → 图文方向无关 → 余弦 ≈ 0（见 3.2）。

**Q：为什么 `W_i` 的绝对大小不重要？**
后接归一化，整体缩放被抹平；权重衰减还会主动把它往小压。

## 六、配对分数矩阵

### 6.1 一个 batch 里有什么

训练时一次取 N 对（图像，文本），并且**已经配好对**：第 i 张图对应第 i 段文字。

```
I_e : [N, d_e]        第 i 行 = 第 i 张图的向量
T_e : [N, d_e]        第 i 行 = 第 i 段文字的向量
```

CLIP 的 N 是 **32,768**。

### 6.2 分数矩阵

把每张图和每段文字都算一次余弦，得到一个 N×N 的矩阵：

```
S = I_e @ T_eᵀ          # 归一化后，余弦 = 点积
S[i][j] = cos(I_e[i], T_e[j])
```

|  | 文1 | 文2 | … | 文N |
|---|---|---|---|---|
| **图1** | `S[1][1]` | `S[1][2]` | … | `S[1][N]` |
| **图2** | `S[2][1]` | `S[2][2]` | … | |
| … | | | | |
| **图N** | | | | `S[N][N]` |

- **行 = 图，列 = 文**
- **对角线 `[i][i]`**：图和它自己的配文 → **正样本**
- **其余 N²−N 个**：错配 → **负样本**
- 矩阵**不对称**：`S[1][2] ≠ S[2][1]`，因为那是两对不同样本

**"一一对应"与"全交叉"是两件事**

| | 事实 |
|---|---|
| **数据层面** | 第 i 张图与第 i 段文字**确实是一对**（本来是同一张图的原配文） |
| **计算层面** | 但不只算这一对，而是**每张图 × 每段文字**全交叉，共 N² 个 |

- **对角线**（i = j）：就是你想要的"一一对应"，N 个真配对
- **其余 N²−N 个**：错配，但**不是废数据——它们就是负样本**

**为什么不能只算对角线**

只算这 N 对，任务就退化成"给每一对打分，越高越好"。模型会找到偷懒解：

> 把所有向量都输出成同一个方向 → 每一对余弦都是 1.0 → 全部满分。

这叫**表征塌缩**，什么都没学到。所以必须有"错的配对"来推远：

```
N = 32,768  →  每个正样本对应 32,767 个负样本
```

**这就是论文用超大 batch 的根本原因**（详见 10.6）。

```python
sim_pos = (I * T).sum(dim=1)   # 只算对角线 → [N]    没有负样本，训不了
S       = I @ T.T              # 全交叉     → [N, N]  论文用的
```

**真正要小心"一一对应"的地方是数据加载**

```
第 i 张图 ↔ 第 i 段文字   必须始终锁死
```

若对图像和文本分别 shuffle、或用两个独立 sampler，第 i 行 I 和第 i 行 T 就不再是原配——但代码照跑、loss 照降，只是学到的东西是错的。这是复现里最常见的**静默失败**。正确做法：先 shuffle 索引，再用同一组索引同时取图和文。

### 6.3 形状 vs 取值范围

| | 说的是什么 | 这里的情况 |
|---|---|---|
| **形状** | 有多少个数、怎么排列 | `[N, N]`，N² 个元素 |
| **取值范围** | 每个数自己有多大 | 每个都是余弦，落在 [−1, 1] |

> ⚠️ 矩阵很大 ≠ 数值很大。N = 32,768 只是格子多（10.7 亿个），每个格子仍是 [−1, 1] 的余弦。

### 6.4 为什么写成矩阵

N = 32,768 时逐对循环要算 10.7 亿次；写成 `I_e @ T_eᵀ` 只是**一次矩阵乘法**，交给 GPU 一次算完。这也是必须做归一化的工程原因（3.3）。

## 七、把分数变成概率

### 7.1 softmax 三步

给一组分数 `z₁ … z_K`（这里 K = N）：

1. **取指数**：`e^{z_k}`，把任意实数变成正数，且保持大小顺序
2. **求和**：`S = Σ_k e^{z_k}`
3. **归一化**：`p_k = e^{z_k} / S`，满足 `p_k > 0` 且 `Σ p_k = 1`

```
p_k = exp(z_k) / Σ_{m=1}^{K} exp(z_m)
```

手算（K = 3，z = [2.5, 0.3, 0.1]）：

```
e^2.5 = 12.18    e^0.3 = 1.35    e^0.1 = 1.11
S = 14.64
p = [0.832, 0.092, 0.076]         ← 和为 1
```

### 7.2 为什么必须先取指数

- 保证非负（概率不能为负）
- 单调递增，大小关系不变（谁大谁概率高）
- 处处可导，方便反向传播（第四章）
- 与对数互为逆运算，和交叉熵的 `−log p` 天然配对（第十章）

### 7.3 按行、按列各做一次

| 做法 | 在什么上归一化 | 回答的问题 |
|---|---|---|
| **按行** | 某张图 vs 所有文字 | 这张图最像哪段文字 |
| **按列** | 某段文字 vs 所有图片 | 这段文字最像哪张图 |

每一行 / 每一列都是一个 **K = N 的分类问题**。

### 7.4 K 很大时会发生什么

CLIP 的 K = 32,768。当所有分数彼此接近（差距远小于 `log K`），分母近似为 `K × e^{z̄}`：

```
p_正确 ≈ e^{z_正确} / (K × e^{z̄}) ≈ 1/K
```

代具体数字（正确类 z = 0.3，其余 32,767 个类 z = 0）：

```
S ≈ 1.35 + 32,767 × 1 = 32,768.35
p_正确 ≈ 1.35 / 32,768.35 ≈ 4.1×10⁻⁵ ≈ 1/K
```

**概率几乎均匀 = 模型什么都没学到。** 问题出在"分数差距太小"，下一章解决。

### 7.5 实现细节

数值上先减最大值再取指数，避免 `exp` 溢出——数学上完全等价：

```
p_k = exp(z_k − max(z)) / Σ_m exp(z_m − max(z))
```

## 八、温度与放大

### 8.1 差距需要多大

要让 softmax 有区分度，分数之间的差距需要达到 **`log K` 量级**：

```
log 32,768 ≈ 10.4
```

而原始余弦差距只有约 **0.3**——差了两个数量级。直接送进 softmax，就是 7.4 那个 `p ≈ 1/K` 的结局。

**解决办法：把所有分数乘同一个系数。**

### 8.2 放大一次试试

乘 `1/0.07 ≈ 14.3` 倍：

```
0.3 × 14.3 ≈ 4.3
p ≈ 4.1×10⁻⁵  →  约 2.2×10⁻³
```

概率提升了约 50 倍，开始有区分度。这个倍数不是手调的——它作为**可学习参数**跟着训练一起优化。

### 8.3 `exp(t)`：这个倍数怎么表示

**`exp(t)` 就是"放大的倍数"，也就是 `1/τ`。** 它是一个可学习的标量，乘在整张矩阵上。`exp` 是指数函数 `e^x`（e ≈ 2.718）。

| 概念 | 符号 | 作用 |
|---|---|---|
| 温度 | τ | 越小 → 分布越尖锐 |
| 逆温度 | `exp(t)` | 越大 → 分布越尖锐 |

标准写法是 softmax 除以温度，CLIP 写成乘法：

```
分数 × exp(t)      ⟺      分数 / τ，其中 τ = exp(−t)
```

所以 **`exp(t) = 1/τ`**，学术上叫 **inverse temperature（逆温度）**，常记作 β。

**为什么写成 `exp(t)` 而不直接学 τ**：

1. **保证为正**：温度必须 > 0，直接学 τ 要额外加约束；学 `t` 再取 `exp`，永远为正。
2. **优化更平滑**：乘性参数在对数空间里更新更稳定。

📌 论文 §2.3 原文意思：温度以"对数参数化的乘性标量"被优化，避免把它当作超参数来调。

**数值对照**：

```
t = 0        →  exp(t) = 1        不缩放
t ≈ 2.66     →  exp(t) ≈ 14.3     论文初始值（对应 τ = 0.07）
t ≈ 4.61     →  exp(t) = 100      截断上限（ln 100 ≈ 4.61）
```

📌 §2.5 明确说**截断在 100 倍以内**——否则分数太大，训练不稳定。

### 8.4 一个标量，乘遍所有格子

不是每类一个温度，也不是每样本一个：

```
S[i][j] × exp(t)     ← 同一个 exp(t) 乘所有 N² 个格子
```

💡 类比：一群人分数都在 85–88 之间，直接排名看不出差距；把分差放大 100 倍，优劣立刻分明。

## 九、完整前向与训练一步

### 9.1 logits 的完整定义

**logits = 放大后的分数 = 过 softmax 之前的原始分数。** 任意实数，可正可负，不要求和为 1。

名字来自 logistic 回归的 "logit"（对数几率），现在泛指"模型最后一层、还没变成概率的输出"。

```
logits[i][j] = cos(I_e[i], T_e[j]) × exp(t)
```

- 形状：`[N, N]`，N = 32,768 → 约 10.7 亿个数
- 每个元素的范围：`[−exp(t), exp(t)]`（因为余弦先落在 [−1, 1]，再乘倍数）

**它存在的唯一用途：喂给 softmax 变成概率。** logits 不是概率，是概率的原料。

### 9.2 一个小例子（N=3）

为便于展示，这里假定倍数已乘上，所以元素不再局限在 [−1, 1]：

|               | 文1 | 文2 | 文3 |
| ------------- | --- | --- | --- |
| **图1** | 2.5 | 0.3 | 0.1 |
| **图2** | 0.2 | 2.8 | 0.4 |
| **图3** | 0.3 | 0.5 | 2.6 |

按行 softmax 后：

|               | 文1             | 文2             | 文3             |
| ------------- | --------------- | --------------- | --------------- |
| **图1** | **0.832** | 0.092           | 0.076           |
| **图2** | 0.064           | **0.858** | 0.078           |
| **图3** | 0.082           | 0.100           | **0.818** |

对角线概率高 → 损失小（算法见第十章）。**损失本质上就是"对角线概率有多低"的度量。**

### 9.3 训练 vs 推理，形状不同

| 场景                 | 形状                     | 含义                       |
| -------------------- | ------------------------ | -------------------------- |
| **训练**       | `[N, N]` = 32768×32768 | 一个 batch 内所有图-文组合 |
| **零样本推理** | `[1, C]`（C = 类别数）  | 一张图对 C 个类别名        |

同一种东西，只是规模不同。推理时 softmax 完取 `argmax`，就是预测类别。

### 9.4 一个训练 step 的完整流程

把前面所有零件串起来（N = 32,768）：

1. 取 N 对图文，分别过两个编码器 → `I_f`、`T_f`
2. 投影 + 归一化 → `I_e`、`T_e`（第五章）
3. `logits = I_e @ T_eᵀ × exp(t)` → 32768×32768 矩阵（第六、八章）
4. 对角线是正样本，其余全是负样本
5. 按行、按列各做 softmax，算对称交叉熵（第十章）
6. 反向传播，两个编码器和 `W_i`、`W_t` 各拿一份梯度（第四章）
7. Adam 更新，学习率按余弦调度衰减
8. 重复 32 个 epoch

📌 `W_i`、`W_t` **没有单独的训练目标**，它们和编码器共用同一个损失、同一次更新。

### 9.5 为什么训练开始时 logits ≈ 0

随机投影 + 随机编码器 → 图文方向无关 → 余弦 ≈ 0（3.2）→ 所有格子都接近 0。

于是 softmax 近似均匀（7.4），损失很高（接近 `log K`），梯度把对角线往一起拉、非对角线往两边推。**训练的过程，就是把这张矩阵从"一片 0"推成"对角占优"。**

### 9.6 一批一个矩阵：矩阵的寿命与作用

**矩阵是"一次性草稿纸"，梯度算完就释放；参数才是跨步留下来的东西。**

| 时刻 | 发生什么 | 矩阵的命运 |
|---|---|---|
| 第 1 步前向 | 取 32,768 对 → 编码 → 算出矩阵 M₁ | 存在显存里 |
| 第 1 步反向 | 用 M₁ 算 softmax、算梯度、更新参数 | 反传要用 M₁，结束才释放 |
| 第 2 步前向 | 按**更新后的参数**重新编码另一批 32,768 对 → 算出 M₂ | 新建，与 M₁ 无任何数值关系 |
| 第 2 步反向 | 用 M₂ 更新参数 | M₂ 用完释放 |

跨步唯一继承的是**参数 θ**（图像编码器、文本编码器、`W_i`/`W_t`、温度 `t`）。矩阵是中间激活，参数是状态。

**每张矩阵起四个作用：**

| 作用 | 内容 | 存续 |
|---|---|---|
| ① 产生当步梯度 | 每行/每列的 softmax 概率减正确答案，得到"10.7 亿个格子谁该升谁该降" | 一步 |
| ② 作为进度体检 | 对角线是否凸起、损失是否从 ln N 下降 | 一步 |
| ③ 逐步累积 | 约 39 万张矩阵的梯度依次叠加，参数才收敛 | 累积 |
| ④ 制造有益噪声 | 每批负样本都不同，梯度带随机波动，不易卡在局部最优 | 累积 |

**只有 ① 是必需的**，②③④ 是它的副产品。

单张矩阵的贡献有多大：

```
θ ← θ − η · ∂L/∂θ        η 是学习率
```

步长由学习率决定，不由矩阵大小决定；一张矩阵对最终模型的影响约为 `1 / 390,000`。第 1 张矩阵说"猫图和狗图还混着"，第 39 万张说"这些已经分开了，只需微调"——**同一件事会被后续矩阵反复复查，早期离谱的梯度不会留下永久伤害。**

📌 **为什么必须重新算，不能复用旧矩阵**：复用 M₁ 等于用旧参数下的向量坐标去指导新参数的更新，梯度是"过期"的，方向可能完全错。MoCo 用队列记忆历史负样本，也要靠动量编码器缓解陈旧性；CLIP 的做法更简单——每步重算，保证梯度描述当前参数的真实状态。

📌 **矩阵的覆盖面 = 负样本的上限**：

```
一张矩阵能提供的负样本 = 当前 batch 另外的 32,767 个
```

- 想记住历史样本继续当负样本，必须显式建队列（MoCo 路线），CLIP 没做；
- 所以负样本规模被 batch size 直接限制 → 必须用 32,768 的大 batch（6.2）；
- 32 个 epoch 的作用是让同一对图文在不同批次里反复出现（有时当正样本，有时当别人的负样本），把覆盖面补回来。

**收束：矩阵随步生灭，参数跨步累积；每张矩阵只留下一条"该往哪走"的方向，丢弃全部数值。** 训练结束后手上只有参数、没有矩阵，这是对的——矩阵本来就不该出现在产出里。

## 十、交叉熵与对称交叉熵

### 10.1 交叉熵是什么

交叉熵度量"模型给正确答案分配的概率有多低"：

```
L = −log p_正确
```

| `p_正确` | 损失 | 含义 |
|---|---|---|
| 0.99 | 0.01 | 几乎确定，几乎不罚 |
| 0.90 | 0.105 | 很自信 |
| 0.50 | 0.693 | 完全没把握（二选一时） |
| 0.10 | 2.30 | 押错了 |
| 0.01 | 4.61 | 严重错误 |
| → 0 | → +∞ | 把正确答案判成不可能 |

📌 概率越高罚得越轻；`−log` 让"接近 0 的概率"受到极重惩罚。它与 softmax（用 `exp`）互为逆运算，天然配对。

### 10.2 梯度与"摊薄"

交叉熵对分数的梯度是：

```
∂L/∂z_k = p_k − y_k        （y 是 one-hot 标签）
```

- 正确类：`p − 1 ≈ −1`，"抬高正确类"的信号还在
- 其余 32,767 个类：各拿 `+1/K ≈ 3×10⁻⁵`，"压低负类"的信号被 K 摊薄到几乎为零

模型只能整体平移，**学不到"区分"**——这就是为什么必须在事前把差距放大（第八章），而不是指望损失自己救回来。

### 10.3 行与列，两个方向

| | softmax 的分母 | 回答的问题 |
|---|---|---|
| 按行 | 该行所有文字 | 这张图最像哪段文字 |
| 按列 | 该列所有图片 | 这段文字最像哪张图 |

同一张 logits，行 softmax 和列 softmax 得到**两组不同的概率**，梯度也不同。只做一个方向，另一个方向就没有被约束。

```
L_行 = −(1/N) Σ_i log p[i][i]
L_列 = −(1/N) Σ_j log p[j][j]
```

**"一行到底在算什么"**（把 N 缩成 4 便于观察）

取"图3"那一行，本来有 32,768 个数：

| | 文1 | 文2 | **文3 ✓** | 文4 |
|---|---|---|---|---|
| 分数 | 2.0 | 1.1 | **5.0** | 1.6 |
| softmax 后概率 | 0.045 | 0.018 | **0.906** | 0.030 |

三步：

1. **取指数**：`e^2.0=7.39`、`e^1.1=3.00`、`e^5.0=148.4`、`e^1.6=4.95`，总和 163.8
2. **归一化**：各自除以 163.8（这行概率之和为 1）
3. **算损失**：正确答案是文3 → `−log(0.906) ≈ 0.098`

**这一行的"结果"就是 0.098**：正确文字拿到 0.906 的概率，离 1 差的那一点就是损失。

再把每一行都算一遍：

```
图1 → 0.10    图2 → 0.35   ← 这张图没匹配好，罚得重
图3 → 0.21    图4 → 0.15
────────────────────────
平均  = 0.20   ← 这就是 L_行
```

⚠️ **最终结果是一个标量数字，不是"某张图被分到哪段文"**。训练目标就是让这个数变小。

**三个容易卡住的点**

1. **为什么"正确答案"就是它自己的配文？** 因为这一批数据是成对取的（第 i 张图配第 i 段文），答案天然落在对角线上——**不是人标的，是配对关系给的**，这就是自监督。
2. **模型会不会背"第 i 个配第 i 个"？** 不会。模型只看得到向量，看不到序号，唯一线索是"方向像不像"。
3. **这和普通图像分类有什么区别？** 操作完全相同（softmax + 交叉熵），差别在类别集合：ImageNet 是固定 1000 类人定标签；这里是**每批动态变化的 32,768 段文字**，答案来自数据本身。

### 10.4 对称交叉熵：取平均

```python
labels = np.arange(n)                                  # 对角线是正确答案

loss_i = cross_entropy_loss(logits, labels, axis=0)    # 按列：文找图
loss_t = cross_entropy_loss(logits, labels, axis=1)    # 按行：图找文

loss = (loss_i + loss_t) / 2                           # 取平均，不是相加
```

⚠️ 是**除以 2 取平均**，不是直接相加——否则学习率相当于偷偷翻倍。严格说两者只差一个常数因子 2，平均与否等价于"学习率是否减半"，实质影响很小；取平均只是为了 loss 的数值尺度不随方向数变化。

**为什么必须算两次：一个 2×2 反例**

| | 文1 | 文2 |
|---|---|---|
| **图1** | 3 | 1 |
| **图2** | 3 | 1 |

按行（图找文）：

- 图1 `[3, 1]`，正确答案是文1 → p = 0.881 → 损失 0.127
- 图2 `[3, 1]`，正确答案是文2 → p = 0.119 → 损失 2.126
- `L_行 = (0.127 + 2.126)/2 ≈ 1.127` ← **抓到了"图2 错配文1"**

按列（文找图）：

- 文1 `[3, 3]`，正确答案是图1 → p = 0.5 → 损失 0.693
- 文2 `[1, 1]`，正确答案是图2 → p = 0.5 → 损失 0.693
- `L_列 ≈ 0.693` ← **完全没察觉**图2 的错误

同一张矩阵，行方向报 1.127，列方向只报 0.693。原因：`logits[图2][文1] = 3` 这个错误高分，在**行**里很突出（同行正确项只有 1），在**列**里不突出（同列两张图都是 3，看起来"平均分配"）。

**三个层面的必要性**

| 层面 | 理由 |
|---|---|
| 防退化 | 只用行方向时，某段文字可变成"万能文本"（对很多图都高分），行方向不检查，列方向才罚——即文献里的 **hub 现象** |
| 梯度均衡 | 两个模态被同等约束，图像侧与文本侧不会一边学得快、一边拖后腿 |
| 经验 | CLIP、ALIGN 都用对称版；单向对比损失通常略差 |

📌 这就是论文 §2.3 的**对称交叉熵**，也是度量学习里的 multi-class N-pair loss（Sohn, 2016），由 Oord et al. (2018) 以 **InfoNCE** 之名推广。InfoNCE 常指单向版，CLIP 用的是对称版。

### 10.5 用 9.2 的 N=3 例子算一遍

按行（图找文）的对角线概率：[0.832, 0.858, 0.818]

```
L_行 = −(log 0.832 + log 0.858 + log 0.818) / 3
     = (0.184 + 0.153 + 0.201) / 3 ≈ 0.179
```

按列（文找图）的对角线概率：[0.826, 0.846, 0.838]

```
L_列 = −(log 0.826 + log 0.846 + log 0.838) / 3
     = (0.191 + 0.167 + 0.176) / 3 ≈ 0.178
```

对称损失 = (0.179 + 0.178) / 2 ≈ 0.179。这个例子里两个方向差不多，因为矩阵"对角占优"；真实训练初期差异会很明显。

### 10.6 为什么 batch 要开 32,768

每个样本的负样本数 = **N − 1**，对称版本约 `2N(N−1)` 对：

```
N = 32,768  →  每行 32,767 个负样本，全矩阵约 10.7 亿个配对
```

负样本越多，"拉近正样本、推远负样本"的信号越充分。**大 batch 不是显存富裕的副产品，而是对比学习的必要条件**（§2.5）。

### 10.7 三个常见误解

1. **"对称 = 矩阵对称"** —— 不是。矩阵本身不对称，对称指的是损失算了两遍。
2. **"两个损失相加"** —— 是取平均。
3. **"对称交叉熵是新损失函数"** —— 本质就是普通交叉熵，只是对行和列各用一次。

### 10.8 附：为什么用对比而不是逐词生成（§2.3）

**① 生成式太慢。** 作者先试了 VirTex 式路线：让 Transformer 逐词生成配文。结果一个 6300 万参数的语言模型，学习 ImageNet 分类的速度比"预测词袋"基线**慢 3 倍**——因为图片配文千变万化，逐词精确预测太难。

**② 换成对比目标再快 4 倍。** 不要求重建文字，只判断"哪段文字配哪张图"。代理任务简单了，保留的信号还在。

**③ 归一化堵住了作弊。** 对比学习有个捷径：不学语义，只把所有向量长度一起放大，正样本点积就变大、损失就下降。L2 归一化（第三章）把这条路封死——**想降损失，只能靠调整方向**。

**④ 与词袋基线的呼应。** 作者最初的基线是词袋（BoW）编码：把词嵌入简单平均成句子向量（见 1.3）。这个"土办法"竟比大模型学得快 3 倍——说明**选对代理任务比堆模型更重要**。

## 十一、速查表

| 名词 | 一句话 |
|---|---|
| 向量 / 维度 | 一串数；数的个数就是维度 |
| 点积 | `Σ aᵢbᵢ`，受长度和夹角同时影响 |
| 余弦相似度 | 除掉长度后的点积，范围 [−1, 1]，只看方向 |
| 嵌入 / embedding | 把图或句压成固定长度向量，语义相近则方向相近 |
| 词嵌入 | 把词压成稠密向量；CLIP 的输入单位是 BPE token |
| L2 归一化 | 除以长度，把向量压到单位球面；归一化后余弦 = 点积 |
| 权重衰减（L2 正则化） | 训练时把权重往小压，与归一化无关 |
| 前向 / 反向 | 输入×参数得输出 / 从损失往回算梯度 |
| 投影层 `W_i`、`W_t` | 线性映射，把两个模态压进同一个 `d_e` 维空间 |
| 共享空间 | 图像和文本可比较的同一个坐标系 |
| 分数矩阵 | `S = I_e @ T_eᵀ`，第 i 行第 j 列 = 图 i 与文 j 的余弦 |
| 正样本 / 负样本 | 对角线配对 / 其余 N²−N 个错配 |
| softmax | 分数 → 概率：取指数、求和、归一化 |
| 温度 τ | 越小分布越尖锐；`exp(t) = 1/τ` 是放大倍数 |
| logits | 放大后、softmax 前的分数；训练时 `[N, N]`，推理时 `[1, C]` |
| 交叉熵 | `−log p_正确`；对角线概率越低罚越重 |
| 对称交叉熵 | 行、列各算一次交叉熵再取平均 |
| InfoNCE / N-pair loss | 上述损失的学术名称；CLIP 用对称版 |
| zero-shot | 没用过该数据集/任务，直接上手 |
| linear probe / 微调 | 冻结主干只训线性层 / 解冻部分或全部参数继续训练 |
