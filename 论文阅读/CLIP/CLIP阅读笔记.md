## 〇、一句话总结

**CLIP 用 4 亿对"图片 + 配文"做对比学习，让模型学会把图像和文字放进同一个"语义坐标系"，于是只要用文字写出类别名，就能在没见过的任务上直接做分类（零样本迁移），且效果能比肩用 128 万张人工标注图片全监督训练的 ResNet-50。**

## 一、读前必备：三个核心概念扫盲

### 1. 嵌入（Embedding）—— 把万物翻译成"坐标"

神经网络不直接理解图片或文字，它只认识数字向量。**嵌入就是把一张图、一句话各自压缩成一个固定长度的向量（比如 512 维的一串数字）**，使得"意思相近"的东西在向量空间里距离也近。

💡 类比：给每张图、每段文字在同一个地图上打一个坐标点。"猫的照片"和文字"a photo of a cat"应该落在地图同一个街区；而"狗的照片"应该离它们远一点。

### 2. 对比学习（Contrastive Learning）—— 连连看式配对游戏

不给模型标准答案（标签），而是给它一批"配对/不配对"的例子：**配对的拉近，不配对的推远**。模型为了玩好这个游戏，被迫学会理解内容。

💡 类比：把 100 张照片和 100 句描述打乱，让模型做"连连看"。想全连对，模型必须真正看懂图里是什么、话里说的是什么——而不能靠背答案。

### 3. 零样本迁移（Zero-Shot Transfer）—— 没见过也能答

训练时从没见过某个数据集/某类任务，测试时直接上手做。比如训练时从没专门学过"区分猫狗品种"，测试时直接给它 37 个品种名让它分类。

💡 CLIP 怎么做到的：它训练时学的是"图和文配不配"。分类时，把每个类别名写成一句话（"一张金毛犬的照片"），看这句话和测试图片"配不配"——**分类问题被转化成了它最擅长的配对问题**。

## 二、背景与动机：为什么要做这项工作？

### 2.1 旧范式的问题（§1）

当时（2021 年）主流视觉模型的训练方式：

```
人工标注 128 万张图片（ImageNet，1000 个固定类别）
        ↓
训练模型预测这 1000 个类别
        ↓
想识别新类别？→ 重新收集标注数据，再训练/微调
```

问题：
1. **类别是封闭集合**——模型只会认这 1000 类，想认新东西就得重新标注、重新训练，成本高；
2. **标注昂贵且难以扩展**——众包标注要符合"机器学习格式"（N 选 1 的金标），无法利用互联网上现成的海量图文数据；
3. **学到的可能很"窄"**——只为 1000 类优化，容易过拟合到特定数据集的"答题套路"。

### 2. NLP 的启发（§1）

同一时期 NLP 已被 GPT 系列彻底改变：**任务无关的预训练**（在海量原始文本上做语言建模）让模型获得了惊人的零样本能力——不针对具体任务训练，直接用自然语言描述任务就能做。

论文的灵魂拷问（§1 原文）：
> "能从网络文本中直接学习的可扩展预训练方法，能否在计算机视觉领域带来类似的突破？"

### 3. 前人试过但规模不够（§1, §2.1）

- Mori et al. (1999)、Joulin et al. (2016)、Li et al. (2017, Visual N-Grams)、VirTex、ConVIRT 等都尝试过"从文字学视觉"，但训练数据只有 10 万~20 万张图，效果差（零样本 ImageNet 仅 11.5%）。
- 另一边，Instagram 标签预测（Mahajan et al. 2018）、JFT-300M（Kolesnikov et al. 2019）等弱监督方法用了百万~十亿级图片，效果虽好，但类别仍是人工限定的封闭集合（1000 或 18291 类），**没有零样本能力**。

**CLIP 的定位：把"自然语言监督的开放性"与"超大规模训练"结合起来。**

## 三、方法：CLIP 是怎么做的？

### 3.1 总体框架（§2，图 1）

分两步：**对比预训练** → **零样本推理**。

#### 第一步：对比预训练

```
一个批次 N 对图文（论文中 N = 32,768）

图像 I₁…N ──→ 图像编码器 ──→ 图像向量 Iₑ₁…N ─┐
                                              ├─→ N×N 相似度矩阵 ──→ 对比损失
文本 T₁…N ──→ 文本编码器 ──→ 文本向量 Tₑ₁…N ─┘
```

- 把批次里每张图、每段文字都编码成向量，并 **L2 归一化**（统一缩放到单位长度，便于比较方向）；
- 算所有"图-文"组合的**余弦相似度**，得到 N×N 矩阵；
- **目标：矩阵对角线（真实配对）的相似度尽量高，其余 N²−N 个错误配对尽量低**；
- 损失函数是**对称交叉熵**：既对"每张图找对文字"算一次损失，也对"每段文字找对图片"算一次，取平均。这就是度量学习里的 N-pair loss / InfoNCE 的变体（§2.3）。

伪代码（论文图 3，注释为笔记所加）：

```python
I_f = image_encoder(I)        # 图像批次 → 特征 [n, d_i]
T_f = text_encoder(T)         # 文本批次 → 特征 [n, d_t]

# 线性投影到共享空间 + 归一化
I_e = l2_normalize(I_f @ W_i)
T_e = l2_normalize(T_f @ W_t)

logits = (I_e @ T_e.T) * np.exp(t)   # N×N 相似度，t 是可学习的温度参数
labels = np.arange(n)                # 对角线是正确答案
loss = (CE(logits, labels, 按行) + CE(logits, labels, 按列)) / 2
```

> 📌 **温度参数 τ（代码中的 t）**：控制 softmax 的"陡峭程度"。τ 小 → 模型更关注难分样本。它不手调，而是作为可学习参数直接优化（初始化为等效 0.07，截断防止 logits 放大超 100 倍）（§2.3, §2.5）。

#### 补充：L2 归一化、投影层与 logits

这部分概念细节已移到单独的基础知识文件，避免与论文主线混在一起：

- **L2 归一化**（为什么必须归一化、数学性质、实现细节、与正则化/LayerNorm 的辨析）→ [CLIP基础知识补充.md](CLIP基础知识补充.md) §2.2–2.3
- **投影层 `W_i` / `W_t`**（是什么、为什么需要、怎么训练出来的）→ [CLIP基础知识补充.md](CLIP基础知识补充.md) §三
- **logits 与 softmax**（logits 是什么、温度为什么必须放大、训练与推理的形状差异）→ [CLIP基础知识补充.md](CLIP基础知识补充.md) §四

> 📌 一句话版本：先投影到共享空间 → L2 归一化（长度变 1，只剩方向）→ 点积得到余弦 → 乘 `exp(t)` 放大 → softmax → 对称交叉熵。

#### 预训练结束时的产出（§2.4–2.5）

训练跑完后，**产出不是分类器，而是一对"通用编码器 + 对齐参数"**：

| 组件 | 形状 | 作用 |
|---|---|---|
| 图像编码器 `θ_I` | ResNet 或 ViT | 图 → `d_i` 维特征 |
| 文本编码器 `θ_T` | 12 层 Transformer，宽 512 | 文 → `d_t` 维特征 |
| 投影 `W_i` / `W_t` | `[d_i, d_e]` / `[d_t, d_e]` | 两种特征压到同一空间 |
| 温度 `t` | 标量 | softmax 的尖锐度 |

- 训练结束时**全部冻结**，存成 checkpoint（`.pt`）
- 共 8 个规模，最好的是 **ViT-L/14@336px**（§2.5），后文默认用它
- ⚠️ **产出里没有任何类别信息**——它不知道 ImageNet 有 1000 类，而这一点正是"能零样本"的前提

#### 第二步：零样本推理（§3.1.2）

预训练结束后，模型只会干一件事：**判断一张图和一句话配不配**。零样本推理的全部技巧，就是**把分类任务改写成配对任务**——不训练任何分类头，只把每个类别名当成一句描述，看它和测试图像谁最配。

**五个步骤**

| 步 | 做什么 | 关键点 |
|---|---|---|
| ① | 列出测试集的类别名（`cat` / `dog` / …），每个套进模板：`"A photo of a {label}."` | 只需要**标签的名字**，不需要任何训练样本 |
| ② | C 句模板句 → 文本编码器 → 投影 `W_t` → L2 归一化 → 得到 `W_cls [C, d_e]` | 每行就是该类别的"分类器权重"；**整个数据集只算一次**，可缓存 |
| ③ | 测试图像 → 图像编码器 → 投影 `W_i` → L2 归一化 → 得到 `x [1, d_e]` | 和训练时的两条前向路径完全一样 |
| ④ | `logits = x @ W_clsᵀ × exp(t)` → `[1, C]` | 形状从训练时的 `[N, N]` 变成推理时的 `[1, C]` |
| ⑤ | softmax → 取概率最大的下标 → 输出类别 | 没有损失、没有反向传播、参数一个都不更新 |

```python
# ② 只做一次：C 个类别 → C 行分类器权重
texts  = [f"a photo of a {c}." for c in classes]        # C 句
W_cls  = l2_normalize(text_encoder(texts) @ W_t)         # [C, d_e]

# ③④⑤ 每张图一次前向
x      = l2_normalize(image_encoder(img) @ W_i)          # [1, d_e]
logits = (x @ W_cls.T) * logit_scale.exp()               # [1, C]
pred   = logits.softmax(dim=-1).argmax(dim=-1)           # 类别下标
```

**和训练时的对应关系（最容易看混的地方）**

| | 训练（第一步） | 推理（第二步） |
|---|---|---|
| 文本侧输入 | batch 里的 N 段真实配文 | 你自己写的 C 个类别模板句 |
| 图像侧输入 | batch 里的 N 张图 | 1 张待测图 |
| 分数矩阵形状 | `[N, N]` | `[1, C]` |
| 什么是正确答案 | 对角线（第 i 图配第 i 文） | 唯一正确类别那一列 |
| 反向传播吗 | 是，更新全部参数 | 否，纯前向 |

💡 论文里一个很漂亮的解读：**文本编码器相当于一个"超网络"（hypernetwork）**——它不输出文字，而是根据你给的类别描述，**现场"生成"一个线性分类器的权重**（§3.1.2）。换个类别集合，就现场换一套分类器，全程不用训练。这也是步骤 ② 只算一次却极其便宜的原因：**成本与类别数成正比，与图片数量无关**。

**用什么模型、什么权重**

| 项 | 说明 |
|---|---|
| 论文默认 | 8 个规模中报告 **ViT-L/14@336px**（ImageNet 零样本 76.2%，§2.5） |
| 权重是否公开 | WIT 4 亿对无法放出，但 OpenAI **开源了 9 个 checkpoint**：RN50 / RN101 / RN50x4 / x16 / x64、ViT-B/32、ViT-B/16、ViT-L/14、ViT-L/14@336px |
| 共享空间维度 `d_e` | ViT-B/32、RN50 为 512；ViT-L/14 为 768 |
| 本地 4GB 显存 | **ViT-B/32** 推理约 1.5GB，可用；ViT-L/14@336px 建议放实验室 GPU |
| 加载后 | `model.eval()` + `torch.no_grad()`，**全部冻结**，本文后面所有零样本实验都默认如此 |

> 代码上就是两行：`openai/clip` 的 `clip.load("ViT-B/32")`，或 `open_clip` 的 `open_clip.create_model_and_transforms("ViT-B-32", pretrained="openai")`。

**在什么数据集上推理**

论文 §3.1.5 一共在 **27 个**分类数据集上做零样本评估，刻意覆盖差异很大的任务类型：

| 类型 | 代表数据集 | 类别数 C |
|---|---|---|
| 通用物体 | ImageNet (1000)、CIFAR-10/100、STL-10、Caltech-101 | 10 ~ 1000 |
| 细粒度 | Stanford Cars (196)、Food-101 (101)、Flowers-102 (102)、FGVCAircraft (100)、OxfordPets (37) | 37 ~ 196 |
| 场景/纹理 | SUN397 (397)、DTD (47) | 47 ~ 397 |
| 遥感/交通 | EuroSAT (10)、RESISC45 (45)、GTSRB (43) | 10 ~ 45 |
| 医学/计数 | PatchCamelyon (2)、CLEVRCounts (8) | 2 ~ 8 |
| 视频动作 | Kinetics-700 (700)、UCF-101 (101)、HMDB-51 (51) | 51 ~ 700 |

三个要点：

1. **标签只用来在最后算准确率**（预测对没对），推理过程中一个标签都不喂给模型——这才是"零样本"的严格含义。
2. `d_e` 固定不变，但 **C 随数据集变**，所以每换一个数据集都要重跑一次步骤 ①②。成本极低，这正是"超网络"的实际价值。
3. **模板也要换**：通用物体用 `"A photo of a {label}."`；OxfordPets 用 `"a photo of a {label}, a type of pet."`；卫星图用 `"a centered satellite photo of {label}."`（§3.1.4）。

**三个常见误解**

| 误解 | 事实 |
|---|---|
| "零样本 = 完全不需要数据" | 不需要**训练数据**，但需要**类别名单**。名字本身就是一点点人工先验，只是量级从"百万张图"降到"几十个词" |
| "一个模型只能做一种分类" | 同一个 checkpoint 换一套句子就换一个分类器，27 个数据集共用同一份权重 |
| "类别名随便写就行" | 写法与模板影响很大：单词 vs 单模板 = ImageNet +1.3%；80 个模板集成再 +3.5%（§3.1.4，详见 4.2） |

### 3.2 数据：自建 WIT 数据集（§2.2）

现有数据集都不够格：MS-COCO / Visual Genome 只有 ~10 万图；YFCC100M 虽有 1 亿图，但清洗后只剩 1500 万（很多"标题"只是 `20160716_113957.JPG` 这种文件名）。

于是作者自建 **WIT（WebImageText）**：

| 属性 | 值 |
|---|---|
| 规模 | **4 亿**（图像，文本）对 |
| 来源 | 互联网公开来源 |
| 覆盖策略 | 用 **50 万个查询词**检索（维基百科高频词 + 二元词组 + 高搜索量词条 + WordNet 同义词集） |
| 平衡策略 | 每个查询词最多取 **2 万**对，防止热门词淹没长尾概念 |
| 词量 | 与训练 GPT-2 的 WebText 相当 |

### 3.3 关键的工程选择：为什么是对比学习而不是生成？（§2.3，图 2）

作者先试了 VirTex 式路线：用 Transformer **逐词生成**图片的配文。结果效率极低——一个 6300 万参数的语言模型，学习速度比简单的"预测词袋"基线**慢 3 倍**。

原因：图片配文千变万化，逐词精确预测太难、太耗算力。换成对比目标（只管"配不配"，不管"具体写了什么词"）后，效率再提升 **4 倍**。

> 📌 **教训（作者原话的意译）**：从自然语言学习，训练效率是成败关键；选择一个"够简单但保留关键信号"的代理任务，比追求精确重建文本更重要。

### 3.4 模型家族与训练细节（§2.4, §2.5）

| 项目 | 内容 |
|---|---|
| 图像编码器 | ResNet-50/101（含 ResNet-D 改进 + 抗锯齿池化 + 注意力池化）×3 种缩放，或 ViT-B/32、ViT-B/16、ViT-L/14 |
| 文本编码器 | 63M 参数 Transformer（12 层、宽 512、8 头），BPE 词表 49,152，最大序列长 76 |
| 缩放方式 | ResNet 按 EfficientNet 思路同时加宽度/深度/分辨率（RN50x4、x16、x64）；文本编码器只加宽 |
| 训练 | 32 epochs，batch **32,768**，Adam + 余弦退火，混合精度，从头训练（不用 ImageNet 权重或预训练语言模型初始化） |
| 算力 | RN50x64：592 块 V100 × 18 天；最大 ViT：256 块 V100 × 12 天 |
| 最强模型 | **ViT-L/14@336px**（ViT-L/14 再在 336 像素高分辨率上多训 1 epoch）。论文中所有"CLIP"结果默认用它 |

## 四、实验与结果

### 4.1 招牌结果：零样本追平全监督（§3.1.3，表 1）

| 模型 | ImageNet 零样本 top-1 | 用了 ImageNet 训练图吗 |
|---|---|---|
| Visual N-Grams (2017) | 11.5% | — |
| **CLIP（ViT-L/14@336px）** | **76.2%** | **一张都没用** |
| 参考：全监督 ResNet-50 | 76.1% | 用了全部 128 万张 |

CLIP 的 top-5 达 95%，追平 Inception-V4。同数据集（YFCC100M）同规模对比时，CLIP 用 **1 个 V100 天**就达到 Visual N-Grams 的水平——证明进步确实来自方法+规模，而非仅仅是算力碾压。

### 4.2 提示工程与集成（§3.1.4，图 4）

直接用类别名单个词做文本有两个问题：
- **一词多义**：ImageNet 里 crane 既是"鹤"又是"起重机"；OxfordPets 里 boxer 是狗还是"拳击手"？
- **分布不匹配**：训练数据里配文大多是完整句子，很少是孤零零一个词。

解决：
1. **提示模板**：默认用 `"A photo of a {label}."`，仅此一招 ImageNet +1.3%；按任务定制（如 `"A photo of a {label}, a type of pet."`）效果更佳；
2. **集成**：用多个不同模板生成多个分类器，在嵌入空间取平均。ImageNet 上集成 80 个模板，再 +3.5%。

**合计提升近 5 个百分点——相当于白嫖 4 倍算力的效果。**

### 4.3 27 数据集大规模对比（§3.1.5，图 5）

零样本 CLIP vs "全监督 ResNet-50 特征 + 逻辑回归"基线：**27 个数据集赢 16 个**。

| 领域 | 代表数据集 | CLIP 表现 |
|---|---|---|
| 通用物体分类 | ImageNet, CIFAR10/100, STL10 | 略占优；STL10 达 99.3%（零样本 SOTA） |
| 细粒度分类 | Stanford Cars (+28.9), Food101 (+22.5) | 大幅领先 |
| | Flowers102 (−12.5), FGVCAircraft (−11.3) | 明显落后 |
| 视频动作识别 | Kinetics700 (+14.5), UCF101 (+7.7) | 大幅领先（语言对"动词"监督更强） |
| OCR | SST2 (+12.4) | 领先 |
| 专门/抽象任务 | EuroSAT, RESISC45（卫星图）, PatchCamelyon（肿瘤）, CLEVRCounts（数数）, GTSRB, KITTI | **明显落后**，有的接近随机水平 |

💡 解读：CLIP 的强弱取决于"这个概念在互联网图文里常不常见"。常见概念（猫狗、食物、动作）很强；专业概念（病理切片、卫星图）或抽象技能（数数）很弱。

### 4.4 零样本 vs 少样本（§3.1.5，图 6、7）

反直觉的发现：**零样本 CLIP ≈ 同特征空间上 4-shot 逻辑回归**；平均而言相当于每类 **20.8 个**标注样本的效率（中位数 5.4，最好达 184 个/类）。

💡 为什么零样本能打过少样本？一张图包含很多视觉概念，只给 1 张示例图，模型不知道你要学的是图里哪个概念；而 CLIP 的零样本分类器是**用自然语言直接"告诉"它概念是什么**——沟通效率完全不同。

但论文也坦承：人类从 0 到 1 个样本有巨大飞跃（OxfordPets 上人类 53.7%→75.7%），CLIP 反而在 0→少样本过渡时性能停滞甚至反降（§4, §6）。**把先验知识融入少样本学习，是明确的改进方向。**

### 4.5 表征质量：线性探针评估（§3.2，图 10、11）

> 📌 **线性探针（linear probe）**：冻结预训练模型，只在其输出的特征上训练一个线性分类器。特征越好，这个简单分类器表现越好——是检验"表征质量"的标准方法。

- 27 数据集上，**所有规模的 CLIP 模型的计算效率都超过所有对比系统**（含 EfficientNet、BiT、SimCLRv2、MoCo、BYOL 等 66 个模型）；
- 最强 CLIP 在 **27 个数据集中 21 个**击败当时最佳公开模型 Noisy Student EfficientNet-L2，平均分高 **5%**；
- CLIP 的 ViT 比 CLIP 的 ResNet 计算效率高约 **3 倍**（佐证了 ViT 在大数据上的优势）。

### 4.6 鲁棒性：最深刻的发现（§3.3，图 13–15）

**背景**：ImageNet 模型在自然分布偏移（换个拍照风格、场景、画风的图片，类别不变）上错误率飙升 5 倍，说明它们可能学了很多只在 ImageNet 分布上成立的"虚假相关性"。

**CLIP 的发现**（零样本 ViT-L/14@336px vs 同等 ImageNet 精度的 ResNet-101）：

| 数据集 | ResNet-101 | CLIP 零样本 | 差距 |
|---|---|---|---|
| ImageNet（基准） | 76.2 | 76.2 | 0 |
| ImageNetV2 | 64.3 | 70.1 | +5.8 |
| ImageNet-R（艺术图） | 37.7 | 88.9 | **+51.2** |
| ObjectNet | 32.6 | 72.3 | **+39.7** |
| ImageNet Sketch（素描） | 25.2 | 60.2 | **+35.0** |
| ImageNet-A（对抗样本） | 2.7 | 77.1 | **+74.4** |

**零样本 CLIP 把"分布偏移鲁棒性差距"最多缩小了 75%。**

但更有意思的是后续实验：一旦把 CLIP 用 ImageNet 数据做适配（微调/线性分类器），ImageNet 精度 +9.2%（相当于 3 年的 SOTA 进步），**鲁棒性优势却几乎消失**。

> 📌 作者推论：**鲁棒性似乎来自"没见过分布特定的训练数据"**——零样本模型无从利用 ImageNet 特有的虚假相关性。大规模、多样化、任务无关的预训练 + 零样本评估，是通向更鲁棒系统的路线。这也是论文对评估方法学的贡献：零样本评估比"同分布测试集准确率"更能反映真实能力。

### 4.7 缩放规律（§3.1.5，图 9）

5 个 ResNet CLIP 模型、44 倍算力跨度、36 个数据集上：平均零样本误差呈 **log-log 线性下降**——和 GPT 的 scaling law 一样，**性能随算力平滑可预测地提升**。这给了"继续堆算力"一个可预期的回报曲线。

### 4.8 数据污染检验（§5）

大模型爬互联网数据，难免"刷题刷到考试原题"。作者用重复检测器排查：35 个数据集中位重叠率仅 2.2%，重叠带来的精度膨胀基本 <0.1%，最大也只有 0.6%（Birdsnap）。结论：**报告的性能是真实的泛化能力，不是背题。**

### 4.9 局限性（§6，作者难得的坦诚）

1. 零样本 CLIP 平均只相当于"ResNet-50 特征 + 线性分类器"，**距总 SOTA 还差约 1000 倍算力**（当时硬件不可行）；
2. 细粒度分类（车型、花种、飞机型号）、数数、真正分布外的任务（如手写数字 MNIST 只有 88%，输给"直接在像素上做逻辑回归"的玩具基线）都很差；
3. 只能在你给的候选类别里做选择，**不能像 caption 模型那样生成开放式描述**（作者建议未来结合对比目标 + 生成目标）；
4. 数据效率差：32 epochs 共看了 128 亿张图，以 1 张/秒的速度要 405 年才能看完；
5. 开发过程中反复查了验证集，不算"纯净"的零样本研究；27 个评估数据集的选择也有与 CLIP"共同适应"之嫌；
6. 从互联网无过滤数据中学到了**社会偏见**（§7： FairFace 探测中，黑人图像被误分为"非人类"类别的比例高达 ~14%；男性图像被贴"犯罪相关"标签的比例是女性的近 2 倍；给女性贴外貌标签、给男性贴高管/医生标签等）。

## 五、全局视角：这篇论文为什么重要？

1. **范式转移**：把 NLP 的"预训练 → 提示（prompt）→ 零样本"范式完整搬进视觉，证明了视觉表征可以不靠人工类别体系，直接从自然语言中学。
2. **连接两个模态**：图像和文字共享嵌入空间这一设计，成为后来多模态模型的基础设施——DALL·E、Stable Diffusion 用 CLIP 衡量"图-文匹配度"，GPT-4V、LLaVA 等视觉语言模型的视觉编码器很多直接是 CLIP 或其变体。
3. **新的评估观**：主张用"跨 30+ 数据集的零样本迁移"而非单一 ImageNet 精度衡量模型能力，并揭示零样本模型天然更鲁棒。
4. **开源**：代码和权重公开，催生了海量后续工作（ALIGN、FILIP、OpenCLIP、SigLIP……）。

💡 一句话记住 CLIP 的历史地位：**它是视觉领域的"GPT 时刻"——证明监督信号可以不必来自人工标注，而可以来自互联网天然存在的图文配对。**

## 六、术语速查表

| 术语 | 含义 |
|---|---|
| Embedding / 嵌入 | 把图/文压缩成向量，语义相近者距离近 |
| Contrastive learning / 对比学习 | 拉近配对样本、推远不配对样本的训练方式 |
| Zero-shot / 零样本 | 没用目标任务的任何训练样本，直接做该任务 |
| Few-shot / 少样本 | 只用每类几个样本 |
| Linear probe / 线性探针 | 冻结模型、只在特征上训线性分类器，检验表征质量 |
| InfoNCE | 对比学习常用损失函数，本质是 N 路分类的交叉熵 |
| 温度参数 τ | softmax 前的缩放系数，控制分布陡峭程度 |
| Prompt engineering / 提示工程 | 设计输入文本模板以激发出更好的模型行为 |
| Hypernetwork / 超网络 | 一个网络生成另一个网络的权重（CLIP 的文本编码器可如此理解） |
| Distribution shift / 分布偏移 | 测试数据与训练数据来源不同导致的性能下降 |
| Effective robustness / 有效鲁棒性 | 超出"分布内精度自然预测水平"的额外分布外精度 |
| Scaling law / 缩放定律 | 性能随算力/数据/参数呈平滑幂律增长的经验规律 |
