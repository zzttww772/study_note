## 摘要（Abstract）

大语言模型（LLM）在进行生成式推理时，其计算与内存需求给实际部署带来了巨大挑战。针对离线推理，一个有前景的方案是**基于卸载的批处理推理**（offloading-based batched inference），它利用主机内存和存储来扩展 GPU 的内存层次。然而，由于 KV 缓存的大小随批大小（batch size）和上下文窗口长度而增长，该方案往往带来相当大的 I/O 开销。

本文提出 **HILOS**，一个利用**近存储处理**（near-storage processing）来提升离线推理吞吐量的框架。HILOS 的核心是“**近存储注意力**”（attention near storage），它将内存密集型的注意力操作卸载到近存储加速器上，从而减少跨系统互连的流量。在注意力近存储的基础上，HILOS 还引入了三项优化：第一，**协同 X-cache** 利用卸载后空闲的主机资源来最小化 KV 缓存 I/O；第二，**延迟 KV 缓存回写**隐藏了存储写入延迟并缓解了存储写放大；第三，一种**内存高效的注意力加速器**，在 NSP 设备的资源约束下维持长序列的高吞吐量。

我们在配备 16 块 SmartSSD 的真实系统上实现并评估了 HILOS。与最先进的基于卸载的推理框架相比，HILOS 实现了最高 **7.86×** 的吞吐量提升，同时能耗降低最高 **85%**。HILOS 的源代码已开源。

## 1 引言（精华）

基于 Transformer 的大语言模型（LLM）处于现代人工智能的前沿，有望大幅提升人类生产力。因此，为这些模型高效支撑**生成式推理**已成为现代计算系统的一项关键挑战。

当前 LLM 系统多聚焦于**在线推理**（online inference），但**离线推理**（offline inference）对于诸多场景同样关键。与强调低延迟（即低 TTFT 和严格 TPOT 约束）的在线推理不同，离线推理通常允许更长的序列、容忍更高的延迟，特别适用于**基准测试**和**信息抽取**等应用。

离线推理的一大挑战是其所需的巨大内存占用。大模型参数和 KV 缓存往往超出单块 GPU 的内存容量，尤其是离线任务中常见的长序列。此时，为满足增长的内存需求而装备多 GPU 的昂贵服务器往往成本高昂；而且这种方法经济性较差，因为 LLM 推理的**解码阶段本质上是内存受限的**，导致昂贵的 GPU 计算单元严重利用率不足。

一个流行的方向是**基于卸载的批处理推理**方法。它通常将模型权重和 KV 缓存卸载到主机内存，若超出主机内存容量则溢出到二级存储。通过批处理多个 token，可重复复用模型权重以提升吞吐量。然而，一个意料之中的后果是 **KV 缓存传输带来的 I/O 开销**，且批越大、上下文越长，开销越严重。我们的研究（§3.1）显示，在基于卸载的批处理推理中，**KV 缓存 I/O 占总推理时间的 60% 以上**。

鉴于这些局限，我们主张采用**近存储处理（NSP）**来解决该瓶颈。NSP 为 KV 缓存存储带来几项关键优势：(1) 可容纳 TB 级 KV 缓存的充裕存储容量；(2) 随设备数量扩展的高聚合带宽；(3) 减少的主机 I/O 开销。

本文提出 HILOS，一个基于 NSP 的高吞吐量离线 LLM 推理框架，运行在真实系统上。HILOS 的核心是“注意力近存储”，它在每个 NSP 设备内的定制加速器中处理与 KV 缓存相关的操作。借助注意力近存储，只有计算结果被送回主机，显著降低了总 I/O 开销。

**主要贡献**：
- 我们提出 HILOS，首个使用现成产品、能高效支撑长上下文（>100K）LLM 的 NSP-卸载系统。
- 我们提出三项关键设计以解决朴素 NSP-卸载系统的局限：(1) 协同 X-cache，允许协同利用主机资源与 NSP 设备；(2) 延迟 KV 缓存回写，解决新 KV 条目低效的主机–存储数据传输；(3) 高效的 NSP 加速器，使长上下文 LLM 具备高可扩展性。
- 我们使用商用 NSP 设备（SmartSSD）在真实系统上实现 HILOS，并将其集成到基于 PyTorch 的 LLM 推理框架中。评估显示相比传统 SSD 方案吞吐量提升最高 7.86×。

## 3 研究动机（Motivation）

本节指认 **KV 缓存 I/O 是基于卸载的批处理推理的主要瓶颈**，并论证我们的 NSP 方案。

### 3.1 性能瓶颈分析

许多现有系统采用大批量离线推理来缓解频繁的模型权重传输开销。然而，这种方法受限于 **KV 缓存随批大小和上下文长度成比例增长**。我们在 A100 服务器（512GB 主机内存，4 块 PCIe 4.0 SSD）上的最先进离线推理系统上验证该瓶颈。图 2(a) 显示 KV 缓存主导了系统内存占用，达到 TB 量级，超出典型主机内存容量。更关键的是，图 2(b) 揭示对于长上下文推理，**系统被数据搬运压倒性地瓶颈化——传输 KV 缓存消耗了超过 60% 的总执行时间**。因此，这削弱了传统批处理策略的优势，因为权重传输占比减小后，批处理可改善的空间变少。

### 3.2 近存储处理的优势

上述研究揭示，KV 缓存传输开销是基于卸载的批处理推理的根本瓶颈。这促使我们探索 NSP 方案，其关键优势包括：

- **第一**，NSP 设备的大容量可容纳 TB 级 KV 缓存。
- **第二**，NSP 缓解了传统多 SSD 系统固有的 PCIe 带宽瓶颈（图 3(a)）。通过在存储附近处理数据，NSP 最小化了主机–设备数据传输（图 3(b)）。
- **第三**，NSP 缓解了对已被权重加载和自注意力计算重度占用的主机资源的争用。

尽管 NSP 前景可期，但**朴素部署并不能保证性能提升**。要发挥其全部潜力需解决若干关键挑战：(1) 确定卸载哪些计算（§4.1）；(2) 在主机与 NSP 设备间高效调度任务（§4.2）；(3) 有效隐藏存储写入延迟（§4.3）；(4) 设计轻量而高吞吐的存储侧加速器（§4.4）。我们用现成组件（SmartSSD）构建了完整系统来应对这些挑战。

## 4 HILOS 设计

### 4.1 近存储注意力（Attention Near Storage）

如 §3 所述，基于卸载的批处理推理在解码阶段承受巨大的 KV 缓存通信开销。在常规存储设备上，该通信必须穿越共享的系统互连。HILOS 用“**注意力近存储**”（ANS）解决该问题，将注意力卸载到存储设备附近的定制加速器。它将海量的 KV 缓存流量**限制在设备内部通路**，仅让注意力的输入和输出穿越共享系统互连。

如图 4(a) 所示，ANS 针对推理的解码阶段：
1. GPU 从主机内存加载所需 LLM 权重；
2. 执行 QKV 投影；
3. 将生成的查询、键、值向量写入 SSD；
4. 近存储加速器通过**私有通路**从本地存储将完整 KV 缓存加载到其 DRAM；
5. 执行注意力计算，并将最终注意力输出传回主机；
6. GPU 随后从主机内存加载 MLP 权重；
7. 执行后续的 MLP 层。

该策略显著减少了数据搬运。在上下文长度 `s`、隐藏维度 `h`、半精度下，基线方案每解码步 KV 缓存的互连读流量为 `4·s·h` 字节。注意力近存储消除了该流量，代之以仅从设备到主机的 `2·h` 字节注意力输出向量。代价是写流量小幅增加，从基线的 `4·h` 字节（新 K 和 V）增加到注意力近存储的 `6·h` 字节（新 Q、K、V）。由于主导的读流量随上下文长度 `s` 缩放，总体流量降低非常可观。比较基线流量 `T_BASE` 与注意力近存储流量 `T_ANS`：

```
T_BASE / T_ANS = (4·s·h + 4·h) / (2·h + 6·h) = (s + 1) / 2  > 1   （∵ s > 1）   (3)
```

要将该方法扩展到多 NSP 设备，我们沿**批维度和注意力头维度**并行化注意力。在批处理推理中，批大小与注意力头数的乘积提供了足够的维度来将工作负载分布到可用 NSP 设备上。为此，预填充阶段以相同方式跨 NSP 设备并行分布 KV 缓存。

该方案遵循近存储处理原则，有效减少了互连流量。然而在实践中，将注意力操作卸载到 NSP 会使性能瓶颈转移——**内部存储 I/O 现在主导端到端延迟**（图 4(b)）。这给实际 NSP 系统带来关键挑战：如何减少内部存储 I/O。幸运的是，卸载使主机严重利用不足（<20%，图 4(c)），主机仅在计算开销较低的 QKV 投影和 MLP 阶段保持活跃。基于这一观察，下一节提出确保主机与近存储设备间有效协同执行的策略。

### 4.2 协同 X-cache（Cooperative X-cache）

为利用基线流程中主机利用不足（图 5(a)），我们提出一种**协同执行调度**，将注意力工作负载在主机与 NSP 设备间划分。回想式 (1) 中键和值缓存是输入激活 `X` 的投影，我们缓存历史上下文的**投影前输入激活 `X`**，而非派生的 K 和 V 张量。我们将此技术称为**协同 X-cache**。

图 5(b) 详述了该流程。定义 `α` 为 X-cache 管理的批比例，剩余 `1−α` 利用存储在 SSD 中的标准 KV 缓存。该参数 `α` 划分**批（b）和头（h）维度，而非序列维度（s）**。在预填充阶段，系统持久化对应于 `α` 部分的输入激活 `X`。在解码阶段，GPU 通过 **GPU-Direct Storage（GDS）** 直接加载这些 X-cache 条目以最小化系统流量，随后通过重新执行投影操作（式 (1)）重新生成所需的 `K` 和 `V` 张量。同时，近存储加速器（§4.1）对 `1−α` 部分的 KV 缓存执行多头注意力。

由于 X-cache（`b×h×s×d`）只需键和值张量组合（`2×b×h×s×d`）一半的存储容量，它有效地将**系统互连流量和闪存读流量都减半**。这带来一个有利的权衡：它利用了 GPU 本会被闲置的高处理能力，同时注意力操作被卸载。由于该重计算与 NSP 设备上的注意力操作**并发执行**，其延迟被有效隐藏。此外，由于对 SSD 写入减少，这正面影响 SSD 耐久性（§6.6）。

**I/O 分析**：为量化协同 X-cache 的影响，我们推导一阶代价模型。假设 16 位精度（每元素 2 字节），通过带宽 `B_PCI` 的主机互连将 X-cache 部分（`α`）从 NSP 设备传输到 GPU 的时间为：

```
T_PCI = α · s · h · 2 / B_PCI
```

令 `C_GPU` 表示 GPU 的 FLOPS 算力。为重新生成 `K` 和 `V`，输入 `X ∈ R^(s×h)` 乘以权重矩阵 `W_K, W_V ∈ R^(h×h)`。每个 transformer 块此额外重计算所需时间为：

```
T_GPU = α · s · h² · 2 / C_GPU
```

存储读取时间由 SSD 带宽 `B_SSD` 决定，为读取 X-cache 数据（`α` 部分）和 KV-cache 数据（`1−α` 部分）之和：

```
T_SSD = [ α·(s·h·2) + (1−α)·(2·s·h·2) ] / B_SSD
```

假设重计算与数据传输良好流水化且可重叠，则有效时间：

```
T_effective = max( T_GPU, T_SSD, T_PCI )
```

由于 `T_GPU` 通常较小，满足 `T_SSD = T_PCI` 的 `α` 通常给出最佳延迟。令 `S_X` 表示 X-cache 大小，则 KV-cache 大小 `S_KV = 2·S_X`。令 `T_PCI = T_SSD`，消去 `S_X` 并解出 `α`：

```
α = 2 · B_PCI / ( B_SSD + B_PCI )
```

这意味着 `B_SSD` 与 `B_PCI` 之比决定了最优 `α`。我们建模 `B_SSD` 随 NSP 设备数量线性扩展，而有效带宽 `B_PCI` 跨多层实测。我们用此公式自动选择最接近 2 的幂的 `α`。

### 4.3 延迟 KV 缓存回写（Delayed KV Cache Writeback）

虽然注意力近存储和协同 X-cache 改善了总体吞吐量，但处理解码阶段的**回写**仍具挑战性。在预填充阶段，KV 缓存采用行式布局（`b×h×s×d`）。X-cache 也采用相同机制，与 K-cache 共享相同大小和布局。该布局确保高 SSD 带宽，因为最小访问粒度（`s×d`）通常超过 4KiB。相反，每次解码迭代生成的小 KV 向量（`1×d`）必须追加到存储上现有的缓存（`s×d`）。为使这些小向量在后续注意力操作中真正可用，必须提交到存储。这一依赖将**存储写入延迟置于关键执行路径上**，并导致低效的亚页粒度写入。

在图 6(a) 的朴素方法中，GPU 生成新 KV 条目后，(1) 每个条目通过直接 I/O 单独写入 SSD；(2) 随后处理单元从存储读取整个更新的 KV 缓存到其本地内存；(3) 一旦新查询向量传输到处理单元，(4) 执行注意力操作。此方法中，SSD 写入位于关键执行路径上。而且，每个 KV 条目（256 字节）远小于 SSD 页大小（4KiB），导致写入性能差。

为此，我们提出**延迟 KV 缓存回写**（图 6(b)）。我们不在每次生成新 KV 条目时直接写入存储，而是在**主机内存中为 KV 数据保留专用缓冲区**，并允许缓冲区直接馈入加速器的片外内存。由此获得的好处是：(1) 写入延迟脱离关键路径；(2) 数据以**页大小块**写入。

延迟 KV 缓存回写的一个剩余问题是，相同的 KV 向量在被溢出（spill）前被冗余发送。为缓解此开销，**主机 CPU 预计算当前查询与缓冲键向量之间的部分点积（`QKᵀ`）**。仅将得到的标量值（蓝色标记）发送到处理单元。

优化后的工作流如下：
1. 新 KV 条目暂存在主机内存缓冲区；
2. CPU 从这些缓冲条目预计算部分 `QKᵀ` 分数；
3. 已存储的 K 和 V 张量从 SSD 读入加速器；
4. 查询、预计算的 `QKᵀ` 标量和新的 V 条目从主机内存传输到加速器；
5. 加速器使用这些组件完成最终注意力计算。

缓冲的值随后在预定的溢出间隔后溢出到存储。鉴于 SSD 写入粒度为 4KiB，每个 KV 条目通常每头 256 字节，性能优化通常以**溢出间隔设为 16** 来实现。

### 4.4 注意力加速器架构（Attention Accelerator Architecture）

虽然已有若干 Transformer 加速器，HILOS 设计了新架构以应对近存储处理的以下挑战：

1. **可用资源受限**。近存储加速器资源预算紧张。例如三星 SmartSSD 采用中等规模的 FPGA，且进一步受 SSD 功耗预算限制。这对长上下文的 softmax 操作尤其成问题。
2. **键的写与读之间的布局冲突**。如 §4.3 所述，新 KV 条目以行式方式添加到现有 KV 缓存。但键矩阵必须以列方式读取（即注意力中的 `Kᵀ`），造成不匹配。
3. **对注意力变体的支持**。现代 LLM 架构日益采用分组查询注意力（GQA）等变体。虽然可用现有多头注意力架构处理，但会造成冗余数据访问。

图 7(a) 描绘了所提加速器的整体数据流。现有空间架构在单次 pass 中计算整个注意力操作，所需片内内存容量随序列长度增长而变得过大。相比之下，我们采用**时间架构**，以块（如每块 128 个 token）处理注意力计算。如图 7(a) 所示，四个硬件单元形成并发流水线，依据数据依赖处理每个块。这一选择大幅降低了资源需求，尤其是片内内存。

**两遍 Softmax（Two-Pass Softmax）**。给定输入向量 `x = [x¹, ..., xˢ]`，softmax 操作为：

```
softmax(x) = [o¹, ..., oˢ],  其中  oᵢ = exp(xᵢ − max(x)) / Σⱼ exp(xⱼ − max(x))     (4)
```

为避免数值不稳定，通常分三遍完成：一遍求全局最大值 `max(x)`，二遍求指数和，三遍做逐元素归一化。对于长序列，这种方法因片外内存流量而产生主要瓶颈。为此，受**在线 softmax 算法**启发，我们设计了如算法 1 的**两遍（而非三遍）**方法。两遍 softmax 通过两个单元完成：**softmax 统计量聚合单元**（图 7(b)）和 **softmax 归一化单元**（图 7(c)）。

在第一遍（图 7(b)）中，统计量聚合单元以 `d_group×128` 元素的块处理输入向量。每个块流经流水化的 max 归约树以计算局部最大值（第 3 行）。该两遍算法的关键促成因素是：用此局部最大值代替全局最大值，通过将其馈入并行指数单元来稳定指数值。结果由加法树聚合以计算部分和（第 4 行）。然后，根据全局最大值是否更新，流式更新单元修改全局和（第 5–9 行）。第二遍（图 7(c)）执行归一化，由逐元素指数和除法组成（第 10–11 行）。对于注意力计算的掩码，两个单元中的 MASK 应用填充掩码和来自主机（§4.3）的预计算标量（第 3、11 行）。

**带在线转置的 GEMV**。GEMV 单元执行查询–键（图 7(d)）和注意力分数–值（图 7(e)）的乘积。查询–键计算中的一个核心挑战是转置键矩阵（`Kᵀ`）的内存布局转换。朴素方案是转置格式存储 `Kᵀ` 或两者都存，但这对 SSD 写入低效或增加冗余写入。利用基于块的机制，我们的设计集成了高效的原位转置模块（图 7(d)）。通过简单地执行局部块转置并匹配正确的 `Q` 块，可**避免全局转置**。因此，该单元将 128×128 的键矩阵方块加载到片内缓冲区（K-Buf），在本地执行转置，然后将转置矩阵存储到另一片内缓冲区（`Kᵀ-Buf`）。最后，转置矩阵被流式传输到 MAC 单元进行分块 GEMV。

**对注意力变体的原生支持**。我们的架构还对 GQA 等注意力变体提供原生支持，其中 `d_group` 个查询头共享单个 KV 缓存。为此，K/V 缓冲区将其值广播到 `d_group×128` 个并行 MAC 单元，以并发处理共享同一 KV 缓存数据的 `d_group` 个查询向量。若无此特性，共享的 KV 缓存会被组内的每个查询冗余读取。部分结果被累加到每个查询的最终输出缓冲区，减少了冗余的片外内存流量。

## 7 讨论（Discussion）

### 7.1 对 ISP 方案的适用性

本文在 NSP 环境（SmartSSD）上开发 HILOS。虽然这是今天或近未来可用的方案，但它有局限：**单个 NSP 设备并不会比常规系统提升内部带宽**。幸运的是，我们设想 HILOS 使用的核心技术也可应用于未来的**存内处理（ISP）**方案，后者在单设备上提供可观的带宽提升。图 18(b) 展示了设想的 HILOS 使能的 ISP 设备，建模于现代 SSD 设计。NAND 闪存阵列提供 16 TB 聚合容量，通过八条闪存通道连接到 SSD 控制器，每条提供 2000 MT/s（总计 16 GB/s）。单封装 LPDDR5X（四个 16GB 通道）作为内部 DRAM 提供 68 GB/s 聚合带宽。由此我们认为，单个 PCIe 4.0 ISP 单元的性能收益，就内部存储带宽（16 个内部 PCIe 3.0 通道共 16 GB/s）、系统互连（四个 PCIe 4.0 通道共 8 GB/s）而言，将与我们使用的四块 SmartSSD 相当。

### 7.2 未来的计算存储设备设计

尽管有 §4.4 和 §5.4 的架构优化，现有 CSD 平台仍有若干局限。具体而言，虽然我们当前的 CSD 设计使 PCIe 3.0 SSD 的带宽饱和，但未来的 PCIe 5.0 设备需要将吞吐量提高四倍才能充分利用存储 I/O，这将使 CSD 系统维持加速比更具挑战性。在这方面，我们分析当前硬件局限并探索架构改进。

- **第一**，随着注意力组大小（`d_group`）增大，softmax 操作主导执行时间，占总执行时间 **50% 以上**，并消耗大部分 DSP 资源（因计算密集的浮点指数运算）。要通过 DSP 并行化匹配假设的 PCIe 5.0 接口带来的 4× 吞吐提升，设计需要**超过 2000 个 DSP**，超出当前 SmartSSD 平台的总容量。我们认为一个合理的方案是为**指数函数提供专用单元**。鉴于指数函数在现代 AI 负载（如 sigmoid 和 GeLU）中的普遍性，专用硬件单元将显著提升 CSD 用于深度学习的可行性。
- **第二**，采用独立时钟域配合 HLS 将极大便利时序收敛。由于当代 HLS 工具强制单一时钟域，它们固有地限制了先进频率优化的范围。支持不同域可让计算密集的 softmax 逻辑以高频运行，同时内存受限的 GEMV 逻辑保持较低频率。这种解耦将在吞吐量与 NSP 严格功耗约束之间提供有利的权衡。
- **第三**，HILOS 的多 SSD 分布式执行模型表明，现有硬件资源与实际运行需求之间可能存在错配。例如，虽然 KV 缓存在多个 CSD 上分区以最大化聚合内部带宽，但这种分布导致每个设备上的存储占用偏低。即使在峰值负载下，每块 SSD 的存储容量开销仍低于 600 GB，使当前 SmartSSD 的 4 TB 容量大部分未被利用。此外，虽然当前 CSD 匹配内部和外部通道带宽（图 18(a)），但大部分流量仍是内部的，使主机到 CSD 的通道利用不足。可通过轻量 SSD 机制实现更高内部带宽，例如粗粒度块级 FTL 映射而非 DRAM 密集的页级映射。这种方法尤其有效，因为我们的设计通过 §4.3 的回写机制确保 KV 缓存读写的顺序访问。就此而言，更均衡的设计是可行的，例如更少容量、更多内部带宽和/或更多每 CSD 的计算能力。我们相信此类修改将带来更具成本效益的系统。

### 7.3 对基于 CXL 架构的适用性

**Compute Express Link（CXL）**提供的低延迟一致性内存访问，有巨大潜力进一步降低 HILOS 中的数据管理开销。我们当前的缓存管理（§4.3）采用主机侧缓冲，随后显式传输到近存储加速器。该开销随溢出间隔（`c`）缩放（如图 13 所示）。随着现代 SSD 采用更大的内部页粒度（如 16 KiB），需要更高效的数据处理，这一瓶颈预计将加剧。

在 PCIe 基础环境中，物理内存隔离需要通过 Xilinx Runtime（XRT）在 FPGA DRAM 与主机 DRAM 之间进行**显式 DMA 编排**。这导致相当大的软件开销和同步复杂性，在将 `c` 从 4 KiB（`c=16`）扩展到 16 KiB（`c=64`）时，吞吐量降低超过 30%（如图 13 所示）。**CXL.mem** 可通过启用**统一地址空间**来解决这些局限，消除显式数据拷贝和 DMA 管理，从而降低延迟并简化底层缓存管理逻辑。

**直接内存访问**。为最小化数据管理开销，编排式 DMA 技术允许加速器直接发起存储 I/O。这缓解了主机管理方案（CPU 管理 NVMe 交互）的低效。HILOS 与此设计原则一致以缓解 CPU 瓶颈。具体而言，我们将内存密集型的多头注意力任务卸载到近存储加速器，从而有效消除 CPU 受限的性能局限。

## 9 结论（Conclusion）

我们提出 **HILOS**，一个通过将 KV 缓存相关操作卸载到近存储加速器来加速离线 LLM 推理的 NSP 方案。通过缓解关键的系统级集成挑战并采用专门的硬件设计，HILOS 在使用基于 PyTorch 的推理流水线的真实系统评估中，相比最先进基线实现了最高 **7.86×** 的吞吐量提升和 **85%** 的能耗降低。
